# content-player-overlay 规格（macOS 内容区播放器覆盖）

描述 macOS 主窗口内容区如何呈现“列表 ↔ 播放器”的切换：列表是常驻底层，播放器作为覆盖层出现，返回时保留列表状态。

## Requirements

### Requirement: content-player-overlay-structure 列表常驻、播放器覆盖

内容区的目的地列表（推荐、热门、分区、关注动态、观看记录、收藏、稍后再看、下载、我的主页、消息、更多）在应用生命周期内保持挂载；进入播放器时在其上方叠加播放器页面，而不是替换列表；离开播放器后移除播放器页面。

#### Scenario: 从列表进入播放器再返回

- **WHEN** 用户在任一列表页滚动后进入播放器
- **THEN** 列表视图不被销毁，播放器覆盖在其上方
- **AND** 用户返回后列表仍在原来的滚动位置，不回到顶部
验收：A1

#### Scenario: 懒加载内容保持

- **WHEN** 列表已经加载了多页内容后进入播放器并返回
- **THEN** 已加载的内容仍在，不重新请求第一页
- **AND** 不出现整页白屏或闪烁
验收：A2

### Requirement: content-player-overlay-inactive 播放时的列表状态

播放器打开时，底层列表不可见、不接收点击、不被辅助功能聚焦；播放器的尺寸与圆角与改动前一致。

#### Scenario: 播放器覆盖时的列表

- **WHEN** 播放器正在显示
- **THEN** 底层列表不可见、不可点击、不被 VoiceOver 聚焦
- **AND** 播放器占满内容区，圆角与尺寸保持原样
验收：A3

#### Scenario: 关闭播放器后恢复

- **WHEN** 用户关闭播放器
- **THEN** 列表立即可见并可交互
- **AND** 若列表原本处于惯性滚动，滚动继续而不被重置
验收：A4

### Requirement: content-player-overlay-regression 既有行为不变

播放器入口、返回按钮、迷你播放器、全屏、自动播放下一条与侧栏折叠等既有行为不变；空状态分支仍正确显示。

#### Scenario: 播放器既有操作

- **WHEN** 播放器显示时用户使用返回、全屏、迷你播放器或自动播放下一条
- **THEN** 行为与改动前一致
验收：A5

#### Scenario: 空状态与未登录分支

- **WHEN** 未登录用户进入“我的主页”，或搜索没有结果
- **THEN** 仍显示对应的空状态或登录提示
- **AND** 从播放器返回后立即可交互
验收：A6

### Requirement: content-player-overlay-build 构建与测试

结构改动不引入构建警告或测试失败。

#### Scenario: 构建与测试通过

- **WHEN** 执行 swift build 与 swift test
- **THEN** 构建无警告，全部测试通过
验收：A7
